# План тестирования приложения «В Хосписе»

## Цель

Проверить основные функции учебного Android-приложения «В Хосписе», оформить чек-лист и тест-кейсы.

## Что проверяю

- запуск приложения, вход и выход;
- главную страницу и меню;
- список новостей: просмотр, сортировку и фильтры;
- панель управления новостями: создание, редактирование, статус и удаление;
- экран «Наша миссия»;
- понятность сообщений об ошибках и основные проверки интерфейса на телефоне.

Не проверяю нагрузку на сервер, безопасность, iOS и функции, которых нет в приложении.

## Виды проверок

- **Smoke-проверка** — приложение запускается, пользователь может войти и открыть основные экраны.
- **Функциональная проверка** — каждая основная функция даёт ожидаемый результат.
- **Проверка интерфейса** — тексты, кнопки, ориентация экрана и увеличенный шрифт остаются удобными для использования.
- **Проверка ошибок** — пустые поля, неверные данные и отсутствие сети.

## Тестовые данные

Для своих новостей использую заголовок с пометкой `QA-DIP`, чтобы не спутать их с данными других студентов. После проверки удаляю только созданные мной записи.

Сервер учебный и общий для студентов. Поэтому после создания новости сразу проверяю её в панели управления. Чужие новости не изменяю и не удаляю.

## Порядок работы

1. Запустить приложение на Android API 36 и проверить вход.
2. Пройти тест-кейсы из Cases.xlsx.
3. Отмечать результат в Cases.xlsx: «Пройден», «Не пройден», «Заблокирован» или «Не выполнен».
4. Для найденной ошибки записать шаги, ожидаемый и фактический результат, сделать скриншот.
5. Удалить свои тестовые новости и вернуть обычные настройки устройства.
6. Подготовить материалы первого этапа для проверки руководителем.

## Материалы первого этапа

- Check.xlsx — чек-лист проверок;
- Cases.xlsx — тест-кейсы и результаты проверок;
- evidence — скриншоты и данные, подтверждающие результаты.
